# Nytka Android People Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The app side of the People milestone: a People tab with person pages, "Who is this?" cards,
a review inbox, a name-suggestion banner, meeting-brief notifications and a consent chime.

**Architecture:** New API clients in `:core` (`core/api`), each its own interface so existing fakes stay
untouched; screens in `:app` under `ui/people/`, a brief worker in `briefs/`, the chime in `capture/`.
View models take the client interfaces and emit typed notices; screens turn them into string resources.

**Tech Stack:** as the app today (CLAUDE.md, "Stack"); no new dependency. ExoPlayer (already used by
`ExoAudioPlayer`) plays clips; `ToneGenerator` plays the chime.

**Spec:** [`docs/specs/people.md`](../specs/people.md). Read it first; this plan only orders the work and
names files and tests. Server API: the server README's "API" table at server `main` `9b649f9`.

## Global Constraints

- CLAUDE.md invariants hold, above all 6 (nothing personal in logs or the debug report) and 7 (never
  `RECORD_AUDIO`).
- A server call is an interface in `core/api` with its Hilt binding in `app/di/<Area>Module.kt`.
  Do not add methods to `PeopleClient`: its fake in `PeopleViewModelTest` would break.
- Every UI string, notification text and channel name goes into `app/src/main/res/values/strings.xml`
  **and** `values-uk/strings.xml`, under a comment header naming the task (`<!-- People: person page -->`),
  appended at the end of the file, so parallel tasks conflict only at the tail.
- View models hold no display text: they emit typed notices (pattern: `VoiceNotice` in
  `ui/voice/VoiceViewModel.kt`). Tests assert on the notice, not on text.
- Older servers: follow the spec's "Older servers" table; reuse `notice()` and `itemNotice()` from
  `ui/ServerNotices.kt`.
- Tests: JUnit 4, hand-written fakes, `MainDispatcherRule`, Turbine where a flow is read, MockWebServer
  for `:core` clients. Names: plain sentences in backticks.
- Each PR: `./gradlew ktlintFormat`, then `./gradlew check assembleOssDebug assemblePlayDebug` green;
  conventional commit; the README section of what it changes in the same PR.

## Review Focus

1. **Nothing applies itself.** Accept, confirm and name routes are called only from a user's tap. Grep
   each diff for `accept`, `cards/`, `review/` calls outside click handlers.
2. **Logs.** No `Log.`/`AppLog` line carries a name, note, fact, line, brief, event title or URL.
3. **Older servers.** A `404` on a route the server lacks never reads as "item gone" and never crashes
   (tests per client and per view model).
4. **Chime.** Silent while muted, disconnected or enrolling (A-P9 tests).
5. **Strings** in both languages (A-P2's parity test).

**Files:**
- Create: `core/.../api/PeopleModels.kt`, `PersonPageClient.kt`, `ReviewClient.kt`, `CardsClient.kt`, `BriefsClient.kt`
- Modify: `core/.../api/ApiModels.kt` (`ServerInfo.FEATURE_PEOPLE = "people"`, `FEATURE_VOICE_GROUPS = "voice-groups"`; `NytkaTask` gains `personId: String? = null`, `personName: String? = null`), `PeopleClient.kt` (`Person` gains `note: String? = null`, `lastSeenAt: String? = null`, `facts: Int? = null`)
- Modify: `core/.../settings/Settings.kt`, `SettingsStore.kt`: `briefNotifications = false`, `notifiedBriefs: List<String> = emptyList()`, `consentChime = false`, `consentChimeMinutes = 15`
- Modify: `app/di/PeopleModule.kt` (bind the three people clients); Create: `app/di/BriefsModule.kt`
- Test: `core/src/test/.../api/PersonPageApiTest.kt`, `ReviewApiTest.kt`, `CardsApiTest.kt`, `BriefsApiTest.kt`; extend `SettingsStoreTest.kt`

**Interfaces** (all `suspend`, all `ApiResult`):
- `PersonPageClient`: `person(id): PersonPage`; `update(id, name: String?, note: NoteChange)` where `NoteChange` is `Keep`, `Clear` or `Set(text)` (sends `note: null` for `Clear`, no `note` for `Keep`) and answers the stored `Person`; `facts(id, before: String?, limit: Int): FactPage`; `addFact(id, text): PersonFact`; `editFact(id, factId, text): PersonFact`; `deleteFact(id, factId): Unit`.
- `ReviewClient`: `review(limit): List<ReviewItem>`; `answer(kind, id, accept: Boolean): Unit`; `suggestions(): List<NameSuggestion>` (sends `status=pending`); `answerSuggestion(id, accept): Unit`.
- `CardsClient`: `cards(): List<VoiceCard>`; `answer(card, CardAnswer)` with `CardAnswer` = `Person(id)`, `Name(text)`, `Skip`, `Reject`; `clipRequest(kind, id): AudioRequest?` (through `NytkaApi.authorized`).
- `BriefsClient`: `upcoming(minutes: Int): List<UpcomingBrief>`.
- Models carry every field of the README's API rows, with defaults so a missing field decodes; ids are `String` (a review `label` id is a segment number sent as a string).

Steps:
- [ ] Write MockWebServer tests first: each path, method, query and body (`note: null` present for `Clear`, absent for `Keep`); decoding with an extra field and with optional fields missing; `204` as `Ok(Unit)`; `404` as `NotFound`, `405` as `Unsupported`, `409` as `Conflict`; the clip request carries `Bearer` and its `toString` hides it.
- [ ] Implement; Hilt bindings.
- [ ] Settings: new fields persisted and read back; `toString` unchanged in what it masks.
- [ ] No strings, no README (nothing a user sees).

   fixed). Rename, merge, delete, delete and forget each work from the person page.

   delete asks first; the deleted fact does not come back after "Regenerate summary".

   shows the banner; Accept names the voice; lines show "Olena"; tap "Olena" opens her page.
5. With voice matching on and two conversations with an unnamed voice: a card appears, its clip plays
   (TalkBack reads "Play clip"), Save names it; Skip hides another for 7 days; Not a person removes one.

7. Meeting briefs on (allow notifications when asked): a calendar event with "Olena" as attendee 30
   minutes ahead brings one notification; the lock screen shows only "A meeting brief is ready"; no
   second notification on the next run.

   screen open, no chime; airplane mode does not matter.

   (server field messages may stay English).
