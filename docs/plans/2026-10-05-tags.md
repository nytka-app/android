# Nytka Android Tags and Roles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tag chips, add and remove, a tag filter on Conversations and People, proposed tags and role
suggestions in the banner, the person page and the review inbox.

**Architecture:** One new client `TagsClient` in `:core` (`core/api`), so the fakes of
`ConversationsClient` and `PeopleClient` stay untouched; optional fields on existing models; a shared
tag sheet and chip row in `ui/tags/`; view models emit typed `TagNotice`s.

**Tech Stack:** as the app today (CLAUDE.md, "Stack"); no new dependency.

**Spec:** [`docs/specs/tags.md`](../specs/tags.md). Server: nytka-app/server `docs/specs/tags.md` and its
plan `docs/plans/2026-10-05-tags.md` (tasks T-1 to T-7). Each task below starts after the server task
whose routes it calls is merged.

## Global Constraints

- CLAUDE.md invariants hold, above all 6: no tag name, role or person name in a log line or the debug
  report.
- Do not add methods or parameters to `ConversationsClient` or `PeopleClient`.
- Every string in `values/strings.xml` **and** `values-uk/strings.xml`, appended at the end under a
  header comment naming the task (`<!-- Tags: chips -->`).
- Gate on `/api/v1/info` features: `tags` (A-T1 to A-T4), `tag-suggestions` (A-T5), `roles` (A-T6).
- Tests: JUnit 4, hand-written fakes, `MainDispatcherRule`, Turbine, MockWebServer for `:core`.
- Each PR: `./gradlew ktlintFormat`, then `./gradlew check assembleOssDebug assemblePlayDebug` green;
  conventional commit; the README section of what it changes.

## Review Focus

1. **Nothing applies itself.** `accept` calls only from click handlers.
2. **Logs.** No tag, role or name in `Log.`/`AppLog`.
3. **Older servers.** No feature flag, no tag UI, no extra call (tests per view model).
4. **Strings** in both languages (the parity test from A-P2).

`addPersonTag`, `removePersonTag` the same; `conversations(tag, before, limit): ConversationPage`;
`people(tag): List<Person>`; `suggestions(): List<TagSuggestion>` (sends `status=pending`);
`answerSuggestion(id, accept): Unit`.

## Manual acceptance on a phone

1. A server without `tags`: no chips, no Tag action, no proposals. No crash.
2. Tag a conversation `work` and `Робота`; chips read `work`, `робота`; remove one; the 21st is refused.
3. Filter Conversations by `work`: only tagged ones, scrolling loads older ones; clear restores the list.
4. With a conversation where someone says "the repairman is here": the banner reads "A voice may be the
   repairman"; Accept; People shows "Repairman", "Name not known yet", chip `repairman`. Later "Thanks,
   Mykola" in the same conversation brings "may be Mykola, the repairman"; Accept renames him.
5. A proposed tag shows in the banner and in the inbox; Accept adds the chip; Reject never brings it back.
6. Ukrainian: every new text reads in Ukrainian.
7. `adb logcat | grep -iE "nytka"` during 2 to 5 shows no tag, role or name.
